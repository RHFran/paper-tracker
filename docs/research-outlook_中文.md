# 六段式精读与本期总结

[首页](../README_中文.md) · [Agent 工作流](agent-workflow.md) · [English](research-outlook.md)

Agent 负责读论文、理解研究设计并提出研究设想。程序负责结构、证据锚点和引用编号的
校验、审计保存以及文本／HTML 排版，不用模板填补缺失内容，也不在渲染器里手写报告
替代研究过程。

## 每篇论文固定六段

1. **问题与设计**：背景中的具体瓶颈，以及总体设计如何回应它。不要把自己的设计解读
   写成作者明确说过的动机。
2. **科学问题**：论文要回答的问题或可检验假设。
3. **方法链**：输入与数据 → 实验或模型步骤 → 验证。保留步骤之间的科学依赖。
4. **结果与亮点**：有单位、有对照的定量结果，以及来源支持的贡献，避免重复叙述。
5. **局限性**：具体的数据、方法、验证或泛化边界。区分作者陈述与基于证据的分析推论。
6. **有何启发**：可以迁移的研究思路或值得继续检验的方向，不能把待做实验写成已证实结论。

内部继续保留原来的 `fields.highlights/question/methods/findings`，以兼容既有接口。
新 Agent 分析增加 `perspective`，包含 `design_logic`、`limitations`、`inspiration`。
每项为 1–3 条 `{text, evidence, kind}`：`reported` 表示作者说明，`inferred` 表示分析推论。
每条都要有该论文原文中连续的 12–180 字符证据片段。程序会在报告中标明两者区别。
`findings` 和 `highlights` 合并为第四段，不再分成两个重复标题。

新任务要求科学问题与方法非空，结果或亮点至少有一条；三个 perspective 字段也不能空。
不能为了凑齐标题编造内容。如果摘要不足以支撑实质性精读，应在筛选决定中说明并排除；
如果可以做有边界的摘要级解读，仍要保留真实证据级别。

## 正文最后形成跨论文判断

「本期总结与研究启发」放在**逐篇精读之后、参考文献之前**。开头的综述导读帮助读者
进入本期主题，结尾则回答：这些论文合起来推进了什么、哪里不同、哪些问题值得继续做。
不要拼贴逐篇摘要，不要强行关联无关主题，也不要把不同基准的准确率当成同一把尺子。

schema 2 的 Agent 结果增加必选顶层 `outlook`：

- `synthesis`：与导读相同的 `paragraphs → sentences → {text, citations}` 结构。
  引用使用全局 `ref` 编号与连续 `evidence`。多论文期次至少涉及两篇；进行比较时引用
  所有参与比较的论文。
- `open_questions`：1–4 个有证据依据的具体开放问题。可以是从论文推导的问题，但应
  以问题的形式表达，不能伪装成作者报告过的局限或领域共识。
- `ideas`：1–4 个研究设想，证据允许时优先给 2–4 个有区别、有价值的方向；窄主题
  一项也可以，不能为了数量硬凑。

每个 idea 必须包含 `status: "proposed"`、`title`、`basis`、`hypothesis`、`experiment`、
`validation`、`expected_value`。其中 `basis` 为 1–3 条有全局引用和原文锚点的依据；
其余四项写清：

- 可检验的科学问题或假设
- 可行的数据、基线、干预与消融实验
- 留出集、验证指标、不确定性，以及什么结果将反驳假设
- 正面或负面结果将帮助做出什么判断

研究设想不是对全球创新性的保证，也不是已经完成的实验。用自然表达和结构区分事实
与设想，避免重复免责声明，但保留重要边界，例如：气候模拟器不等于语言模型；
模拟某个数值模式不等于通过真实世界验证；生成图像看起来逼真不代表保留了科学信息。

## 校验、空期与旧结果

程序核查结构、长度、语言、引用编号、来源锚点和 proposed 状态；不能证明语义必然成立、
实验可行、科学正确或全球新颖。渲染器拒绝错位引用与已改变的锚点，转义 HTML，不调用模型。
结构化内容会保存到审计记录。

没有入选论文时，synthesis 段落、open_questions 和 ideas 都为空，不编造研究启发。
已冻结的 schema 1 任务仍可按旧结构恢复，升级不会重写既有报告或投递封套；修订报告要
走显式修订／投递流程，不能覆盖已领取的消息。

离线验证：

```sh
python -m unittest discover -s tests -p test_outlook.py -v
python -m unittest discover -s tests -p test_agent_jobs.py -v
```

测试使用合成数据；测试通过不等于真实模型或科研内容已完成质量评估。
